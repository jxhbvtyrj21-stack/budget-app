# ADR 0017. Використання хвилин GitHub Actions (O-8)

- **Статус:** прийнято (вирішено)
- **Дата:** 2026-10-06
- **Закриває:** O-8 (`docs/architecture.md`, розділ 4)
- **Пов'язані рішення:** A-12, A-33 (`docs/architecture.md`, розділ 1); розділ 5.6; ADR 0001

## Питання

O-8 (технічне): чи є обмеження на хвилини CI. Для приватного репозиторію хвилини Windows-runner'ів витрачаються з підвищеним коефіцієнтом, а безкоштовний ліміт обмежений.

## Контекст

Розділ 5.6 уже розподіляє завдання так, щоб важкі Windows-завдання не запускалися на кожен push:
- `lint` і `core-tests` — на `ubuntu-latest` для кожного push і PR;
- `windows-tests` — лише для PR у `main` і push у `main`;
- `build-check` — лише для push у `main` або вручну;
- `release.yml` — лише за тегом `v*` або вручну.

## Рішення

Чинна схема розділу 5.6 є остаточною політикою. Вона розрахована на найменш сприятливий випадок — приватний репозиторій з обмеженими хвилинами — і не залежить від того, чи є репозиторій публічним. Додатково:

1. **Без надлишкових запусків.** Немає запусків за розкладом (cron), нічних збірок і матриць з кількома версіями Python чи Windows: одна версія Python (3.12) і один Windows-runner (`windows-latest`).
2. **Скасування застарілих запусків.** Для `ci.yml` використовується `concurrency` з `cancel-in-progress: true` у межах однієї гілки чи PR.
3. **Зміни лише документації** (`docs/**`, `*.md`) не запускають `ci.yml`.
4. **Ручний запуск** (`workflow_dispatch`) дозволений для `build-check` і `release.yml`.
5. **Windows-перевірки** (`windows-tests`, `build-check`, `release.yml`) залишаються основною перевіркою Windows-артефактів і не прибираються задля економії хвилин.

## Наслідки

- O-8 закрито; відповідне рішення в `docs/architecture.md` — A-33.
- Нових workflow, завдань чи залежностей не вводиться; правила застосовуються під час створення `ci.yml` і `release.yml` на етапі реалізації.
- ADR 0001–0014 не змінюються.
